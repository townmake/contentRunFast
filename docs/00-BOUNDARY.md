# 系统边界（已确认）

## 1. 一句话

选品系统继续当 **商品真实身份 + 调研真相源**；本系统当 **营销版本与实验闭环**。

## 2. 职责切分

| 能力 | 选品系统 (ToBetterLiveBra) | 本系统 (0_0_run_fast) |
|------|---------------------------|------------------------|
| 开发项目 / 简报 / 痛点 / 探索 / PK | ✅ 主库 | 只读拉取 |
| 待上架 ProductListing / 内容生产 | ✅ 主库 | 只读拉取（待建 API） |
| 素材多版本 / 审核 / 优胜 / 回滚 | ❌ | ✅ |
| 美客多官方改图 / 改 Listing | ❌ | ✅（MVP） |
| A/B 或分时实验 | ❌ | ✅（二期为主，MVP 可手工记） |
| 广告创建 / 预算写入 | ❌ | 二期+，视权限 |
| 供应商 / 报关 / 利润试算全链路 | ✅ | ❌ 不搬 |
| ERP 订单库存回款 | ERP | 只读合并利润口径（二期） |

## 3. 同步方向（第一期）

```
选品 ──读──► 本系统（MCP 调研 + Listing 只读）
本系统 ──写──► 美客多等平台 API
本系统 ──可选回写──► 选品（第二期：优胜素材）
```

第一期 **只读不写回选品**，降低耦合。

## 4. 主键对齐

| 概念 | 主键 |
|------|------|
| 内部待上架商品 | `product_listing_id`（选品 `ProductListing.id`） |
| 无上架记录时 | `dev_project_id` + 主推 `platform_sku` |
| 平台链接 | `ml_site` + `platform_item_id` |
| 竞品/对标 | `platform_product_id` / `sku_id` |
| 简报来源 | `stakeholder_brief_id` |
| 本系统素材版本 | 自增 `creative_version.id` |

## 5. 硬约束

1. 美客多更新图片前必须先读完整图片数组，再整表写回。
2. 生成图不得改变实物外观/虚构认证；发布前人工审核。
3. 分时对比 ≠ 严格随机 A/B；记录价格/促销/库存/广告状态。
4. 利润优先用 ERP 结算口径，不单信平台 ROAS。
